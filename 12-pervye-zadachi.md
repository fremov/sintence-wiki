# 12. Первые задачи

Лесенка упражнений. Каждая ступень учит одному и использует то, что ты освоил
на предыдущей. **Ничего не меняй в `main`** — только ветка `learning`.

Для каждой: прочитай указанный файл целиком, потом тесты, потом пиши свой код.

## Ступень 0. Освоиться (без правок)

1. Собери `.\build.ps1 -Debug`, прогони `sintence_tests.exe`. Количество тестов — запиши.
2. Запусти Debug-копию на порту 8778, сделай `curl .../api/health`, найди строки
   этого запуска в журнале.
3. Запусти `npm run dev:mock` и погоняй сценарии в браузере.
4. Пройди `main.cpp` сверху вниз со страницей 4 открытой рядом.

## Ступень 1. Чистые функции в `core/`

Цель: привыкнуть к циклу «тест → код» без сети и без окон.

- **1а.** Прочитай `core/game_mode.cpp` и `tests/test_game_mode.cpp`. Добавь тест на
  случай, который не покрыт (например, `ModeOf(0, "")`). Он зелёный? Значит ты
  понял контракт.
- **1б.** `core/hotkey.cpp`: найди, какие сочетания недопустимы, и добавь 3–4 теста на
  граничные клавиши (F1, F12, `Ctrl+Space`).
- **1в.** `core/overlay_bounds.cpp`: нарисуй на бумаге два монитора и окно на стыке,
  предскажи результат `FitOverlayBounds`, потом проверь тестом.

## Ступень 2. Разбор JSON в `data/`

- **2а.** Прочитай `data/live_client_json.cpp` и `tests/test_live_client_json.cpp`.
  Возьми `tests/data/allgamedata_practice.json`, найди поле, которое сейчас не
  разбирается (например, что-то из `gameData`), и напиши тест на его разбор — **красный**.
- **2б.** Добавь поле в тип `core/live_game.h` и в разбор, чтобы тест позеленел.
  Поле необязательное (`std::optional`) и устойчиво к отсутствию.
- Учит: защитный разбор, фикстуры, путь «сырой JSON → тип ядра».

## Ступень 3. Метрика в `analysis/`

- Прочитай `analysis/party.cpp` или `analysis/profile_summary.cpp` и их тесты.
- Придумай маленькую метрику над готовыми данными (например, «золото в минуту» по
  `LiveGame`: данных хватает). Реализуй чистой функцией и покрой таблицей значений.
- Учит: чистые функции, отсутствие ввода-вывода.

## Ступень 4. Эндпоинт

- Добавь в `LiveApiServer` простой read-only эндпоинт на основе чистой функции из
  ступени 3 (например, `/api/live/summary`).
- Обработай `503`, когда матча нет.
- Проверь `curl`-ом на Practice Tool (запусти тренировочный режим).
- Обязательно: схема и мок в `sintence-web`, если интерфейс будет читать. Если
  интерфейс не трогаешь — поле необязательное, версию не поднимай.
- Учит: контракт, коды статусов, связь C++ ↔ интерфейс.

## Ступень 5. Показ в интерфейсе

- В `sintence-web` покажи новое значение в табло (`components/`), сперва на моках
  (`npm run dev:mock`).
- Учит: полный цикл «данные → API → экран».

## Ступень 6. Своя идея

Придумай и согласуй с заказчиком (**до кода**: что увидит игрок, источник данных,
сколько запросов к Riot). Подходящие направления для новичка — всё, что строится на
Live Client и не требует нового сервера: статистика матча, форматирование, настройки.

## Как проверять себя

- Тест красный → зелёный: **виден** ли провал до кода?
- Нет ли предупреждений компилятора?
- ASan молчит (Debug)?
- Журнал без «ОШИБКА:»?
- Прошёл самопроверку со страницы 8?
- Слои соблюдены (страница 3)?
