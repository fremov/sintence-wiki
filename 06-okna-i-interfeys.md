# 6. Окна и интерфейс

## Идея: приложение = веб-страница в окне

```
sintence.exe (один процесс)
 ├─ поток: HTTP-сервер 127.0.0.1:8777  (cpp-httplib)   ← данные + статика
 └─ главный поток: окна Windows с WebView2             ← показывают страницу из сервера
```

WebView2 — встроенный Chromium Windows 11. Пользователь не видит ни адресной строки, ни
вкладок. Электрон не нужен.

**Почему HTTP, а не прямой вызов C++ из JS:** API проверяется `curl`-ом, интерфейс
пишется на моках без C++, а C++ не изучает COM-API WebView2. Цена — открытый
локальный порт (закрыт от сети, см. страницу 5).

Два окна, **одна и та же страница `dist/`**, разные маршруты:
- оверлей — маршрут по умолчанию (`App.vue`);
- окно статистики — `#/profile`.

## Окна (`src/app/`)

| Файл | Что |
|---|---|
| `overlay_window.cpp` (1850 строк) | окно поверх игры; WinAPI: `CreateWindowEx`, хуки, `WM_*` сообщения; WebView2 внутри |
| `profile_window.cpp`, `stats_window.cpp` | окно статистики |
| `tray_icon.cpp` | значок в трее и меню |
| `webview_lockdown.cpp` | выключает DevTools, F5, Ctrl+F/P/S, масштаб, контекстное меню, новые окна |

Свойства оверлея, которые легко сломать:
- окно **не активируется** по клику (`MA_NOACTIVATE`): фокус уводил игру под ограничение
  кадров фоновых окон;
- показывается без фокуса клавишей **peek** (по умолчанию `Ctrl+X`), хук клавиатуры
  ничего не «съедает» (PgDn и Tab оверлей не трогает);
- над игрой — только если игра или оверлей активны; клик по другому окну уводит панель
  под него (`EVENT_SYSTEM_FOREGROUND`);
- работает только поверх **Borderless**-окна игры; поверх эксклюзивного полноэкрана
  Windows не рисует ничего;
- ничего не внедряется в процесс игры (Vanguard это не любит и Riot запрещает).

## Сообщения интерфейс ↔ окно

Настройки окна интерфейс шлёт сообщениями `chrome.webview.postMessage`:
`overlay/config` (размер, якорь, клавиша, язык), `overlay/drag`, `overlay/resize`,
`overlay/close`, `discord/config`. C++ **только проверяет границы**
(`core/overlay_bounds`, `core/hotkey`), решения принимает интерфейс. В ответ идут
сообщения вроде `overlay/bounds`.

Правило: **логику, у которой нет привязки к Windows, выноси в `core/`** — так
`overlay_bounds` и `hotkey` покрыты тестами, хотя окно тестировать нельзя.

## Интерфейс: `sintence-web`

Vue 3 + Vite + TypeScript + zod.

```
sintence-web/src/
├─ api/          client.ts, schemas.ts (zod-схемы всех ответов)
├─ composables/  useHealth.ts и другие «хуки» опроса
├─ components/   табло, карточки, советы
├─ overlay/      поведение окна оверлея
├─ profile/      окно статистики
├─ settings/     настройки, горячие клавиши
├─ data/         Data Dragon (иконки, названия), бейджи
├─ i18n/         ru / en
├─ mock/         данные для dev:mock
└─ lockdown.ts   гашение «браузерных» действий
```

Иконки и названия берутся из Data Dragon/CommunityDragon по id, которые отдаёт
C++ (поэтому в паке и API — только id).

Сборка: `npm run build` → `dist/` → `build.ps1` вшивает в exe (`EmbedApp.cmake`).
`SINTENCE_WEB_DIR` подменяет вшитое папкой на диске для разработки.

## Языки

Русский и английский. Язык выбирает интерфейс (`localStorage['sintence.lang']`),
C++ узнаёт его из `overlay/config` и держит для трея/уведомлений (`app/ui_text`).
В ответах API кроме русского текста идут **коды** (`reason`, `code`) — по ним
интерфейс выбирает свой перевод.

## Если задача — «поменять то, что видит игрок»

Чаще всего это **два изменения**: данные в C++ (+ тест + схема) и показ в Vue.
Начинай с контракта (страница 5): сначала договорись, какое поле появится,
потом пиши обе стороны. Интерфейс удобно делать первым на моках
(`npm run dev:mock`).
