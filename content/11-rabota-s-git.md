# 11. Работа с git

## Устройство

- `sintence-workspace` — мета-репозиторий; репозитории проекта подключены
  **подмодулями**. Он хранит лишь «на каком коммите стоит каждый».
- Каждый подмодуль — обычный самостоятельный репозиторий: коммиты и push делаются
  **внутри него**.
- `sintence-wiki` — этот репозиторий, тоже подмодуль.

## Твоя ветка в приложении

В `sintence-app` создана ветка **`learning`** — от `main` на момент создания
(коммит `2e11244`, версия `0.2.31`). Ты работаешь только в ней: `main` остаётся
рабочей версией заказчика.

```powershell
cd sintence-app
git switch learning
git status
```

Подмодуль часто стоит на «голом» коммите — всегда проверяй `git branch --show-current`
перед правкой.

## Рабочий цикл

```powershell
git switch learning
# ...правки...
.\build.ps1 -Debug            # собрать с ASan и тестами
build\tests\Debug\sintence_tests.exe
git add src/core/xxx.cpp tests/test_xxx.cpp     # конкретные файлы, не "git add ."
git commit -m "Что сделано и зачем (по-русски)"
```

Правила коммитов проекта:
- по одному коммиту на смысловую единицу;
- сообщение по-русски: что и **зачем**;
- не коммить `info.txt`, `build/`, `out/`, секреты;
- перед коммитом: сборка без предупреждений, **все** тесты зелёные.

## Свежие изменения из main

Когда заказчик меняет `main`, подтяни их в свою ветку:

```powershell
git fetch origin
git merge origin/main        # или git rebase origin/main, если освоишь
```

Конфликты разбирай внимательно; не знаешь, чья правка верная, — спроси.

## Push

- `learning` пушится в `origin/learning`: `git push -u origin learning`. На GitHub ветки
  пока нет — первый push создаст её.
- **Не пушь в `main`** приложения и не открывай PR без договорённости с заказчиком.
- В `sintence-data` и `sintence-web` свои правила: push в `sintence-data` — боевая
  выкладка. Туда без согласования не лезь.

## Указатели подмодулей в мета-репозитории

Заказчик сам обновляет указатели в `sintence-workspace` после push в подмодулях.
Ты в мета-репозитории править их не обязан. Если нужно: сначала push в подмодуле,
потом `git add sintence-app && git commit` в корне workspace.

## Вики

Правишь вики — коммить в `sintence-wiki` и пушь в её `main`: это учебный
репозиторий, он твой.

## Безопасность

- Не используй `git push --force`, `git reset --hard`, переписывание истории без
  понимания последствий — это разрушает чужую работу.
- Не клади в репозиторий секреты (`.env`, ключи, токены) — `.gitignore` защищает от
  части, но не от всего.
