# 4. Путь данных

Главная страница. Здесь — что происходит от запуска `.exe` до картинки на экране.
Читай рядом с кодом.

## 4.1. Запуск: `app/main.cpp`

`main()` ничего не считает — он **собирает части и связывает их** (так задумано).
По порядку:

1. **Порт**: `PortFromEnv()` — `SINTENCE_PORT` или 8777.
2. **Аргументы командной строки** (нужны самообновлению):
   - `--apply-update` — этот exe скачанная новая версия, он заменяет старый и выходит;
     неполные аргументы — запись в журнал и выход с кодом 2;
   - `--updated-from`, `--update-failed` — запуск после обновления (уведомление у трея);
   - `--autostart` — запуск из автозапуска Windows, окно статистики спрятано.
3. **Одна копия**: `AcquireSingleInstance(port)`; вторая копия лишь показывает окно первой.
4. **Журнал**: `OpenLogFile(...)`.
5. **Источник живого матча**: `LiveClientSource` (ходит в игру) обёрнут в
   `CachedLiveGameSource`: снимок живёт 900 мс, «игры нет» — 2 с, параллельные
   запросы ждут один общий. Дальше все спрашивают кеш, не игру.
6. **Сервер Sintence**, если адрес задан: `ServerAuth` (токен ищет свой поток),
   `RiotApiClient`, `ProfileService`.
7. **Пак и справочники**: `PackStore`, `MetaStore`, `TrendsStore` и один `PackUpdater`,
   который качает все три; затем `BadgeStore` + `BadgeUpdater`.
8. **Проверка интерфейса**: есть ли вшитый или `SINTENCE_WEB_DIR`; иначе окно с ошибкой.
9. **История**: `SqliteMatchStore::Open(":memory:")` + `HistoryService`.
10. **Лобби**: `LobbyService` (LCU).
11. **`has_content`** — «есть ли что показать на оверлее», со сглаживанием
    (`ContentDebounce`: включается сразу, выключается после 10 с тишины).
12. **Службы, которым нужен `has_content` или состояние**: `AppHeartbeat` (пульс на сервер),
    `AppUpdater` (получает `has_content` как `busy` — не ставит обновление посреди игры),
    `LiveGameService` («сейчас в игре», друзья), `ActiveUsersUpdater` (значок «S»).
13. **`LiveApiServer`** + `Set*` (мета, тренды, обновление…) и `Start()`. Порт занят —
    окно с ошибкой и выход с кодом 1.
14. **`OverlayOptions`**: адрес, `profile_url` (`#/profile`), `has_content`;
    `DiscordPresence` (выключен, пока интерфейс не пришлёт `discord/config`).
15. **`RunOverlay(options)`** — окна WebView2 и цикл сообщений Windows; возвращается
    при выходе из трея.
16. **Выход**: `heartbeat->SendClosed()` (до 2 с), `updater.OnExit()` (может поставить
    обновление), затем `std::_Exit` — намеренно, чтобы фоновые потоки не держали процесс.

Видно общий приём: **зависимости передаются снаружи ссылками/указателями**
(внедрение зависимостей руками). `LiveApiServer` не создаёт ничего сам и не знает,
откуда данные.

## 4.2. Живой матч

```
игра ──https://127.0.0.1:2999/liveclientdata/allgamedata──► LiveClientSource::Fetch
                                                              │ текст JSON
                                                              ▼
                                       live_client_json.cpp: ParseAllGameData
                                                              │ LiveGame (core/)
                                                              ▼
                                           CachedLiveGameSource (кеш 900 мс)
                                                              │
                      ┌───────────────────────────────────────┴────────────┐
                      ▼                                                    ▼
          LiveApiServer: GET /api/live                          /api/preferences, /api/profiles…
                      │ JSON
                      ▼
          Vue-интерфейс (периодический опрос) → табло
```

Ключевые детали:
- Используется **один** запрос `allgamedata`, а не три: отдельные эндпоинты снимаются в разные
  моменты, и снимок противоречив.
- Нет игры → порт закрыт → `LoadGame()` возвращает `nullopt` → `/api/live` отвечает **503**
  («временно нет»), а не 404.
- Сертификат игры самоподписанный: `enable_server_certificate_verification(false)` (так же и в `lcu_client.cpp`) —
  допустимо **только** для `127.0.0.1`.
- В Practice Tool роль `NONE`, у ботов Riot ID вида `Garen#BOT`: код должен это переносить.

## 4.3. Лобби до матча (LCU)

`LobbyService` читает клиент League (lockfile → порт и пароль → HTTPS на `127.0.0.1`).
Фазы клиента: `ChampSelect`, `GameStart`, `InProgress`, `Reconnect`. Выбор чемпиона —
из LCU; экран загрузки — из spectator-v5 через сервер.
Результат — снимок `Lobby` (`core/lobby.h`) → `/api/lobby`.

Запись в клиент (руны, заклинания) — **только** `data/lcu_actions` и **только по клику**
пользователя (`POST /api/champselect/runes|spells`, защита `TrustedWrite`).

## 4.4. Профили игроков

```
/api/profiles ─► ProfileService ─► RiotApiClient ─► ServerConfig (HTTPS, токен)
                                                      └► сервер: /v1/riot/<хост>/<путь>
                                                           └► Riot (ключ на сервере, кеш)
```

Профиль игрока = 3 запроса (puuid, ранг, мастерство). Лобби = 30 запросов, около
40 секунд — поэтому ответ приходит **с прогрессом**: интерфейс опрашивает, пока не
дойдёт до 100%.
Хост Riot зависит от запроса: региональный (`europe`) — account/match, платформенный
(`ru`) — остальное. Ошибка хоста **выглядит как «ранга нет»**, а не как ошибка.

## 4.5. История матчей (окно статистики)

`HistoryService` → профиль целиком из кеша сервера (`/v1/history`, мгновенно) →
докачка нового → запись в SQLite `:memory:` (`SqliteMatchStore`, схема
`history_schema.sql`) → `/api/profile`, `/api/matches`, `/api/matches/{id}[/timeline]`.
Файлов у пользователя нет: после перезапуска всё снова из серверного кеша.

## 4.6. Советы по сборке («пак предпочтений»)

Сервер раз в 6 часов и при смене патча собирает по ранговым матчам **пак** — JSON
со статистикой: какие руны/предметы/прокачку берут чемпионы против кого.
Приложение (`PackUpdater` → `PackStore`) сверяет `sha256` раз в 30 минут и качает новое.
`PreferencePack::Lookup` ищет совет по **лестнице отката**:

1. матчап + корзина ранга → 2. матчап + любой ранг → 3. «против всех» + ранг → 4. «против всех».

В паке **только id** (руны, предметы, заклинания); названия и иконки интерфейс берёт
из Data Dragon. Запрос `/api/preferences` в матче строится по табло, до матча — по
`?champion=&role=&enemies=`. Пока пак не приехал — 503, нет сервера — 501.

## 4.7. Вспомогательные потоки

| Служба | Что | Период |
|---|---|---|
| `PackUpdater` | пак, мета, тренды | 30 мин; пока пака нет — раз в минуту |
| `BadgeUpdater` | правила плашек | 10 мин; пока нет — раз в минуту |
| `AppHeartbeat` | «я запущен» + состояние | 60 с и сразу при смене состояния |
| `AppUpdater` | новая версия | первая проверка через 5 с после старта, в игре опрос раз в 10 с, при выходе, по кнопке |
| `ActiveUsersUpdater` | значок «S» у других пользователей | кеш 10 мин |

Потоки живут рядом с HTTP-сервером; общее состояние защищено `std::mutex`
(см. страницу 9).
