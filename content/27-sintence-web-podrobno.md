# 27. sintence-web: устройство интерфейса

`sintence-web` — Vue 3 + TypeScript + Vite + zod. Одна сборка используется в трёх
окнах приложения: оверлей, профиль и статистика. C++ не вызывает функции Vue напрямую;
граница — HTTP JSON и сообщения `chrome.webview`.

Контракт конкретных ответов описан на страницах [16](16-kontrakt-match-lobby-profili.md),
[17](17-kontrakt-sovety-spravochniki.md) и [18](18-kontrakt-istoriya-ladder-prochee.md).

## Точка входа и маршруты

`src/main.ts` сначала устанавливает browser-lockdown и подсказки, затем выбирает
корневой компонент по hash:

| URL | Компонент | Окно |
|---|---|---|
| `/` | `App.vue` | оверлей |
| `#/profile` | `profile/ProfileApp.vue` | окно профиля |
| `#/stats` | `stats/StatsApp.vue` | статистика в матче |

В режиме `VITE_API_MODE=mock` транспорт подменяется до монтирования приложения, а
`MockSwitcher` получает сценарии. В обычной сборке ветка моков и динамические импорты
выбрасываются сборщиком.

## Слой API и zod

`src/api/client.ts` — единственное место, где вызывается `fetch`. Транспорт имеет
небольшой интерфейс и может быть заменён моковым:

```typescript
export type ApiResult<T> =
  | { kind: 'ok'; data: T }
  | { kind: 'status'; status: number; error?: string; code?: string }
  | { kind: 'invalid'; path: string; issues: string[] }
  | { kind: 'network' }
```

Каждый `200` проходит через zod-схему из `src/api/schemas.ts`. Это четыре разных
состояния, а не исключение для всего приложения:

- `ok` — тело соответствует контракту;
- `status` — C++ ответил не `200`: например, 501 или 503;
- `invalid` — HTTP успешен, но C++ и интерфейс разошлись;
- `network` — exe не отвечает.

Путь и первые замечания схемы логируются один раз, чтобы частый poll не заливал
консоль. Компонент обязан обработать каждый вариант.

Для POST `apiPost` добавляет `Content-Type: application/json` и
`X-Sintence-Action: 1`. Вызов действия должен исходить из обработчика клика, а не из
`watch` или poll.

## Общий poller

`src/composables/usePoll.ts` содержит `createPoller`:

- одновременно выполняется максимум один запрос;
- если во время запроса пришёл новый trigger, после него выполняется один отложенный;
- следующий таймер ставится после завершения, а не заранее;
- видимая и скрытая панель могут иметь разные интервалы;
- переход hidden → visible вызывает внеочередной запрос;
- `stop()` останавливает poll навсегда, например после 501.

Это защищает от наслоения запросов, когда сервер или Live Client отвечает медленнее
обычного.

## Оверлей

Основные composable и компоненты:

| Участок | Содержимое |
|---|---|
| `useHealth` | версия API, состояние сервера и обновления |
| `useLiveGame` | `/api/live`, 503 без матча, замедление в скрытом состоянии |
| `useLobby` | фаза, пики, экран загрузки |
| `useProfiles` | профили и прогресс докачки |
| `usePreferences` | советы активному игроку |
| `AdvicePanel` | руны, предметы, навыки и fallback |
| `PlayerCard` | участник, стиль, предметы и действие по клику |
| `overlay/config.ts` | размер, якорь, autoShow, клавиша |
| `overlay/host.ts` | `chrome.webview.postMessage` и входящие сообщения |

Названия чемпионов, предметов, рун и заклинаний приходят в виде ID/ключей. Перевод и
иконки берутся из Data Dragon и CommunityDragon, а не из C++.

## Профиль

`ProfileApp.vue` объединяет шапку, сводку, список матчей, аналитику, мету, динамику,
друзей и настройки. `useMatchHistory` имеет отдельный цикл, потому что загрузка
истории двухфазная:

1. `/api/profile` сообщает статус и прогресс;
2. `/api/matches` перечитывается только когда количество сохранённых матчей изменилось;
3. открытая подробность заказывает `/api/matches/{id}/timeline`;
4. timeline может быть `202`, `200` или `502` с повтором.

Свой Riot ID сохраняется в `localStorage`, чтобы окно могло показывать последний профиль
при временно выключенном клиенте League. Это не кеш данных Riot: сами матчи остаются в
памяти C++ и на сервере.

## Моки

Сценарии лежат в `src/mock/scenarios.ts`, данные — в `src/mock/data.ts`,
`src/mock/profile.ts` и `src/mock/trends.ts`. Мок обязан соответствовать zod-схеме,
иначе `vue-tsc` или runtime-проверка покажут расхождение.

Полезные сценарии:

```text
?scenario=champselect
?scenario=practice
?scenario=idle
?scenario=offline
?scenario=invalid
?scenario=noclient#/profile
?scenario=clientstart#/profile
```

Моки нужны для визуальной проверки и переходов состояния. Они не доказывают работу
Win32-фокуса, LCU или реального сервера.

## Окно и сообщения WebView

В браузере `chrome.webview` отсутствует, поэтому функции host молчат. В WebView2:

- страница отправляет `overlay/config`, `overlay/drag`, `overlay/resize`, `overlay/hide`,
  `overlay/close` и `discord/config`;
- C++ проверяет границы, меняет окно и отправляет `overlay/bounds`;
- `storage` синхронизирует язык, клавиши и настройки между окнами одного origin.

Страница не должна использовать WebView API для данных. Данные всегда идут через
локальный HTTP API, чтобы тот же экран работал в браузерных моках.

## Язык

Словари `src/i18n/ru.ts` и `src/i18n/en.ts` должны иметь одинаковую форму `Messages`.
Коды `reason`, `code`, `errorCode` переводятся интерфейсом; русский текст C++ остаётся
запасным для неизвестного кода.

Язык хранится в `localStorage['sintence.lang']`. При смене интерфейс шлёт событие
`storage`, а оверлей передаёт выбранный язык в C++ для трея и уведомлений.

## Как добавить поле

1. Сначала изменить источник или API C++ и определить статус/значение по умолчанию.
2. Обновить zod-схему; новое поле сделать необязательным, если нужна совместимость
   со старым exe.
3. Обновить типы, которые выводятся из схемы, и моки.
4. Обработать `status` и `network` в composable.
5. Показать значение на моках и в живом окне, если доступно.
6. При удалении поля или смене типа синхронно поднять версии API.

Не помещай расчёт доменной метрики в шаблон Vue, если он уже считается C++. Формат и
источник должны оставаться в одном месте.

## Проверка

```powershell
cd sintence-web
npx vue-tsc --noEmit
npm run build
npm run dev:mock
```

Для визуальной проверки открывай мок в обычном браузере. Встроенное окно WebView2
намеренно отключает DevTools, F5 и контекстное меню.
